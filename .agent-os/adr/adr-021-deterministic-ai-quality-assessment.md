## Context

AI 분석 결과의 형식·입력 근거 연결·완성도를 사용자 점수와 구분해 설명할 품질 신호가 필요하다. 별도 AI 평가기는 의미 품질을 넓게 판정할 수 있지만 추가 비용, 지연, 그리고 평가 결과의 비결정성을 만든다.

## Decision

성공한 Analysis History마다 결정론적 Quality Rule Set으로 AI Quality Assessment를 계산하고, 사용한 평가 기준 버전을 함께 보존한다. 첫 버전은 별도 AI 평가기 호출이나 동일 입력 반복 실행을 하지 않는다.

AI Quality Assessment와 Analysis Execution Version은 별도 1:1 테이블이 아니라 같은 `analysis_history` 행의 결과 스냅샷 필드로 영속 저장한다. 분석 이력 삭제 시 해당 스냅샷도 같은 행과 함께 삭제된다.

Analysis Execution Version은 이력서 진단, JD 매칭, 품질 평가 컴포넌트를 각각 기록한다. 한 컴포넌트의 모델이나 프롬프트만 변경되어도 해당 분석 결과의 생성 조건을 구분할 수 있어야 한다.

각 컴포넌트의 모델·프롬프트·평가 기준은 서버 설정의 명시적 Version Identifier로 저장한다. Git 커밋 SHA와 프롬프트 원문은 버전 식별자로 저장하지 않는다.

현재 보존해야 할 기존 사용자 분석 이력이 없으므로, 품질·실행 버전 필드는 새 스키마부터 생성한다. 과거 이력 백필이나 `평가 정보 없음` 전환 UI는 범위에서 제외한다.

각 사용자 표시 주장(이력서 진단의 강점·개선안, JD 매칭의 강점·Gap·제안)은 이력서 또는 JD 입력 사본의 Evidence Citation 배열을 하나 이상 포함한다. 품질 평가는 인용문이 지정한 원문에 실제 존재하는지와 모든 필수 항목이 근거를 갖는지를 검증한다.

`quality-v1`의 총점은 응답 형식 준수 30점, 원문 근거 연결성 50점, 결과 완성도 20점으로 계산한다. 동일 입력을 반복 실행해야 하는 분석 일관성은 첫 버전의 평가 항목에서 제외한다.

각 Quality Metric은 기대한 검증 수 중 통과한 수의 비율로 0점부터 100점까지 계산하고, 총점은 해당 비율에 가중치를 곱해 합산한다. JSON 자체를 해석할 수 없는 응답은 품질 감점이 아니라 Result Unavailable로 처리한다.

Quality Status는 90점 이상 `검증 양호`, 70점부터 89점 `일부 확인 필요`, 69점 이하 `재분석 권장`으로 표시한다. Result Unavailable는 점수 없이 `평가 불가`로 표시한다. 낮은 상태는 검증에 실패한 항목과 재시도 행동을 보여 주되 분석 결과를 숨기지 않는다.

사용자 화면에는 품질 점수·항목별 결과·평가 기준 버전만 표시한다. 모델명과 프롬프트 버전은 Analysis Execution Version으로 이력에 보존하지만 사용자 화면에는 표시하지 않는다.

사용자는 각 강점·부족 역량·제안의 Evidence Citation을 기본 접힘 상태의 `근거 보기`로 확인할 수 있다. 모달은 사용하지 않으며, 표시 내용은 출처 유형과 최대 200자의 인용문으로 한정한다.

낮은 Quality Status는 분석 결과를 숨기거나 실패로 바꾸지 않는다. 사용자는 낮은 품질 안내와 재시도 동작을 보며, 원래 분석 결과는 계속 확인할 수 있다.

내부 `FAILED` 분석 이력은 사용자 화면에서 Result Unavailable로 표시한다. 화면은 결과를 만들지 못했다는 사실, 입력 사본 보존, 원인별 다음 행동만 안내하며 기술 예외나 품질점수를 노출하지 않는다. 재시도 가능한 공급자·응답 검증 문제에는 같은 입력 재시도를, 입력 부족·수집 문제에는 입력 보완 동작을 제공한다.

이력서 진단과 JD 매칭은 하나의 완성된 분석 묶음으로 취급한다. 둘 중 하나라도 실패하면 부분 결과와 품질점수를 노출하지 않고 Result Unavailable로 처리한다.

## Consequences

- 품질 평가는 기존 분석 응답만으로 재현 가능하며 추가 Gemini 비용과 지연이 없다.
- 품질·실행 버전은 분석 이력 상세와 항상 함께 조회되므로, 첫 버전에는 별도 테이블 조인이 필요하지 않다.
- 이력서 진단·JD 매칭·품질 평가의 버전은 서로 독립적으로 추적한다.
- 버전 비교는 코드 변경 이력 대신 명시적 모델·프롬프트·평가 기준 식별자를 기준으로 한다.
- 과거 사용자 데이터 마이그레이션과 재평가는 필요하지 않다.
- 인용 검증은 원문 연결성과 누락을 판정할 뿐, 주장의 의미적 사실성 전체를 보증하지 않는다.
- 모델·프롬프트 버전은 운영자의 재현·장애 분석·변경 비교에만 사용하며 사용자 UI 계약에서 제외한다.
- 원문 근거는 사용자가 직접 확인할 수 있지만, 기본 접힘으로 결과 화면의 밀도를 유지한다.
- 낮은 품질은 사용자 흐름을 차단하지 않고, 해석 주의와 재시도 기회를 제공한다.
- 실패한 분석 이력에는 품질점수를 만들지 않는다.
- 분석 실행 실패는 숨기지 않되, 사용자에게는 복구 가능한 Result Unavailable 상태로 투명하게 안내한다.
- 부분 성공 결과는 노출하지 않으며, 품질 평가는 완성된 분석 묶음에만 생성한다.
- 이후 의미 기반 AI 평가기를 도입하면 별도 Feature Spec과 새 평가 기준 버전으로 추가하며, 기존 평가 기록은 변경하지 않는다.
