# 분석 진행 상태 피드백 수용 기준

- **AC-01 시작 직후 안내**: 유효한 입력으로 분석을 시작하면 결과 화면에 전체 진행 상태와 최소 하나의 진행 항목이 즉시 표시되고, 사용자는 현재 분석이 실행 중임을 알 수 있다. (REQ-01)
- **AC-02 이력서 단계 표시**: 이력서 진단 요청이 실행 중일 때 이력서 준비/분석 항목이 `진행 중`이고, 진단 응답 전에는 후속 분석을 `완료`로 표시하지 않는다. (REQ-02)
- **AC-03 선택 항목 표시**: 선택하지 않은 분석 항목은 진행 목록에 나타나지 않으며, 선택된 JD 적합도·키워드·ATS·문장 첨삭은 실제 실행 그룹에 맞는 상태를 가진다. JD 적합도와 키워드 선택 시 네트워크 요청은 하나만 실행된다. (REQ-03)
- **AC-04 병렬 실행 중 유지**: 하나의 분석 항목이 먼저 끝나도 다른 선택 항목 또는 이력 저장이 진행 중이면 전체 상태는 `분석 진행 중`으로 남는다. 모든 요청이 종료된 뒤에만 `분석 완료`가 된다. (REQ-04)
- **AC-05 부분 실패 안내**: 일부 항목만 실패하면 성공한 결과는 확인할 수 있고, 실패 항목과 실패 안내가 보이며, 전체 상태는 성공으로 표시되지 않는다. (REQ-05)
- **AC-06 진단 실패 처리**: 이력서 진단이 실패하면 후속 분석을 완료로 표시하지 않고, 실행할 수 없었던 항목은 건너뜀 또는 차단 상태로 구분하며 실패 원인과 다음 행동을 안내한다. (REQ-05)
- **AC-07 중복 실행 차단**: 분석 요청이 진행 중인 동안 시작 동작을 다시 수행해도 동일한 실행이 중복 생성되지 않는다. 새 분석으로 전환한 뒤 이전 실행의 늦은 응답이 새 화면을 변경하지 않는다. (REQ-06)
- **AC-08 접근성 상태**: 진행 영역은 보조기술에 상태 변화를 전달하고 `aria-busy`를 진행 중에만 사용한다. 성공·실패는 텍스트로도 식별 가능하며, 모션 감소 설정에서 필수 정보가 유지된다. (REQ-07)
- **AC-09 계약 회귀 없음**: 기존 분석 요청·결과 표시·내보내기·새 분석 동작과 standalone JD fetch/interview 흐름이 진행 상태 추가로 깨지지 않는다. 서버 endpoint나 응답 계약 변경은 없다. (REQ-08)

## 완료 조건

- 모든 AC가 테스트 결과와 연결된다.
- 문서·코드·테스트·CI 결과가 일치한다.
